## 实际角色对话

| 场景 | 实际结果 |
| --- | --- |
| 妈妈分享明天下午还书的安排 | 静默生成 short 记忆，没有创建待办、提醒或公开确认 |
| 同一安排改为后天 | 保持原 key，更新内容并保留原始来源与修订 |
| 取消还书安排 | 从有效列表和检索中移除，保留取消审计 |
| 妈妈疲惫、想安静休息 | 简短回应，没有后台术语、建议清单或提醒承诺 |
| 明确要求记住虚构点心偏好 | 一条明确记忆、一条确认回复，没有重复写入 |
| 孩子考虑周末做纸船、尚未决定 | short / tentative，回忆时保留不确定性，没有自动创建任务 |
| 引用、玩笑 | 未变成家庭事实或任务 |
| 旧称 `@小忆` 与自然称呼“小艺，……” | 正常识别；小艺正确自报姓名 |
| 个人合成便签 | 仅本人空间可见；群中不能检索，匿名个人接口返回 401 |

最终并发脚本以母亲、孩子身份同时提交请求，两条消息服务端创建时间相差约 6.3 毫秒。孩子询问纸船计划，母亲取消还书安排；两项处理均完成，仅回复孩子，取消的安排不再检索为有效。

## 测试中修复的问题

1. 前一位成员的求助污染当前陈述的参与判断：区分 `latest_message` 与背景消息，并由独立策略拦截未点名的普通近况陈述。
2. 没有创建提醒却承诺到时提醒：明确约束只有成功提醒记录才能支持未来触达承诺。
3. 模型用 `state: cancelled` 格式更新记忆，导致取消被忽略：提供独立记忆状态增量，并兼容旧字段；兼容分支要求已知记忆 key、高置信意图及最新原文明确结束依据，拒绝否定、考虑或假设表达。
4. 已过期但尚未归档的计划被更新时沿用旧有效期：新一轮有效观察重新计算期限；旧来源重放不能复活过期事项。

默认短期七天、临时状态最多一天、周期整理六小时，新观察会将下一次复核提前至五分钟内。设置更改整理间隔即时调整下次运行时间，且不推迟已待处理的新观察。

自动提取仍依赖消息分析成功；周期整理采用本地确定性规则。语义相近但不能证明相同的条目不自动合并，完全相同的自动条目才合并。私人空间和群组始终分别整理。
