# 后台 skill 与上下文管理

聊天消息仍按会话内来源顺序处理。目录 skill 的 `skill_load` 调用会派发为独立持久化任务，前台不发送接单话术，使用一张持久化进度卡展示实际阶段后即可继续聊天。简单的记忆查询、待办查询等工具调用直接等待结果后回复，不创建进度卡。每个 worker 从自己的需求快照继续工具循环，不接收后续聊天指令。现有固定步骤任务与 skill 任务共用后台并发额度。

## 配置

在环境变量或 `.env` 中配置，重启后生效：

| 变量 | 默认 | 含义 |
| --- | --- | --- |
| `BACKGROUND_GROUP_LIMIT` | 2 | 每会话后台执行上限 |
| `BACKGROUND_GLOBAL_LIMIT` | 4 | 全局后台执行上限 |
| `BACKGROUND_MAX_ROUNDS` | 12 | 每次 skill 执行模型轮数 |
| `BACKGROUND_TIMEOUT_SECONDS` | 600 | 每次后台执行总期限，不含排队 |

应用采用单后端进程，不能通过增加 uvicorn workers 扩容调度。后台不占前台调度额度，模型供应商仍可能对所有调用共享限流。

## 记忆与权限

任务保存来源消息、发起人、settings、工具调用快照和上下文检查点。原提示中嵌入的检索记忆在派发时移除，执行前重新按来源目标检索；过敏、禁忌等安全约束另行加入。工具检索得到的记忆也纳入版本追踪。后续对话仅提供任务状态与结果摘要。

记忆统一使用现有可见性和生命周期规则，所有更新经过 `Record.set` 的版本递增与持久化内容比较，避免并发覆盖。编辑接口接受可选 `version`，旧客户端兼容；新聊天界面会提交版本，过时编辑返回 409。修改、删除、过期和相关新事实在结果生成后及投递前核验。模型生成期间发生变化时丢弃旧草稿，从原需求与最新事实重新生成。待处理记忆冲突或模型无法确认关键约束时暂停为 `waiting_input`。

skill worker 只开放读取能力；建议保存在任务结果中，不会自动变成长久记忆。固定步骤任务仍需原有明确授权。后续聊天不修改、取消或重规划任务，待核对任务需核对事实后重新发起。

## 状态与恢复

`GET /api/groups/{gid}/agent/status` 增加 `foreground` 与 `background_tasks`。WebSocket `task_update` 提供任务 ID、来源消息、标题、状态、阶段和更新时间，不包含完整快照。聊天页的后台任务列表在刷新和重连后恢复。

任务使用确定的来源 key 派发，结果按任务、状态、重试次数幂等投递。生成与投递状态分离，投递失败只重试消息发送。管理端保留取消、失败重试操作，skill 任务不能通过固定步骤表单扩大权限。

重启后排队任务继续执行，中断的只读 skill 从原始快照重新运行；检查点用于保留诊断信息。固定步骤已成功的动作沿用回执。写入前保存开始记录；若进程中断或超时而没有完成回执，需要核对，禁止盲目重放。同步线程/进程工具超时不保证底层工作立即停止，因此未确认的写入始终保留保护记录。

## 验证

`python -m pytest` 包括慢任务期间聊天、同会话与全局并发限制、重启恢复、记忆失效与安全约束重算、冲突暂停、越权写入拒绝、同步工具卸载、超时和结果投递重试测试。前端使用 `npm run build` 检查类型与打包。


## 进度与结果展示

普通聊天的 conversation run 只用于内部执行记录，不再自动产生卡片或出现在置顶任务栏。目录技能及其他复杂工具调用派发后创建唯一进度卡，通过 task_update / card_update 更新执行规划、联网搜索（仅实际搜索工具执行时）、思考中等阶段。完成后卡片默认精简，可展开详情；结果直接作为普通消息展示，不显示引用块，也不拼接原始用户指令作为标题。

旧的 conversation 进度卡和固定接单话术以 hidden 标识从聊天中隐藏，原始消息与执行记录保留。历史后台结果去除自动添加的原指令前缀，不再显示卡片引用；用户原消息不隐藏。部署后需重启后端并刷新页面以加载接口和前端更新。
