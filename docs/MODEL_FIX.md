# 真实联测问题修复

## 原因与修复

### 写入成功后回复HTTP400

固定合成协议请求复现了服务商错误：`The reasoning_content in the thinking mode must be passed back to the API.` 原实现为服务端已执行的动作构造了一个没有推理字段的助手工具调用，同时在真正模型工具循环中丢弃了该字段。

- 已执行动作改为明确标注来源消息的执行记录，不再伪造模型工具调用；后续模型仅能读取，不能再次写入。
- 模型真实返回的`reasoning_content`在本轮工具循环中原样传回，纳入上下文预算；不保存到聊天、任务或日志，也不展示给用户。
- DeepSeek常规回复默认显式关闭思考模式；可通过`DEEPSEEK_THINKING=enabled`选择开启。结构化分析固定使用非思考模式。其他兼容模型不发送DeepSeek专属参数。
- 回复只确认当前消息对应的动作，不重新处理历史命令。重试读取待办当前完成状态、提醒真实发送次数等状态，避免用旧执行结果误述当前情况。

DeepSeek的[思考模式协议](https://api-docs.deepseek.com/guides/thinking_mode/)要求工具循环携带对应推理字段；本次还以固定合成数据验证了开启思考模式的一轮真实工具调用可以完成。

### 结构化JSON解析失败

- 区分空内容、截断、格式错误、拒绝和HTTP错误。只接受完整JSON对象或单个完整JSON代码块，不从任意文本抽取大括号，也不修补部分决策。
- 结构化输出初始预算4096 tokens；仅在200响应的JSON为空、无效或被截断时重试一次，最大预算8192。HTTP400/401、网络错误和拒绝不会被自动循环重试。
- 无效分析不进入业务写入；两次均失败时提供可理解的错误。两次请求的有效用量会合计，指标同时记录HTTP尝试次数。
- 错误仅显示状态与经过校验的请求ID，不显示可能包含私人提示词的服务商原始错误体。

DeepSeek的[JSON输出说明](https://api-docs.deepseek.com/guides/json_mode/)也记录了空输出与token预算问题。

### 同源自动/手动记忆重复

- 明确“记住”请求跳过同一消息的自动记忆提取，由授权动作创建唯一确认记录。
- 自动写入遇到同源的显式确认记录时复用它；不会把其他来源或其他人工记录合并。
- 迁移版本3仅处理能够由原消息证明是明确记忆命令的同源自动条目。保留人工记录，将自动副本标记为合并并移出检索，同时将原内容记入修订历史；不创建来源抑制，不物理删除记录。

## 回复失败后的恢复

新增任务状态`reply_failed`及`action_status`、`reply_status`：动作完成后回复失败，执行任务保持成功，回复单独标为失败。群Agent页、私人会话和执行记录均提供“仅重试回复”。

重试复用持久化执行记录，不再调用成功的写入工具；如果回复消息已持久化，则直接完成恢复。旧版本中有明确成功步骤的失败任务会在迁移时重新归类，不会自动重放动作。
