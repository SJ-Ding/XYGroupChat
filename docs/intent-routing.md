# 小艺识别与明确请求回复

- 显式 `@小艺` / `＠小艺` 可位于句首、句中和句尾；`@小忆` 保留兼容。裸称呼“ 小艺，…”仍只在句首触发。引用、转发、代码和其他名字不产生直接召唤。
- 原始数据内容中的 @ 不会被删除或变成授权。只有实际消息地址会从窄命令解析中剥离，例如“五分钟后提醒我吃药@小艺”的提醒内容为“吃药”。
- 明确意图无需“请、帮我”或问号：语义为 request、target=agent、置信度至少0.85时直接回复。具体的近况/改期陈述仍保持安静；指向家庭成员的问题按已有观察策略处理。理解、技能加载和实际写入权限分开校验。
- 就医语义增加 scene 和 operation：`family-appointment` + `query` / `book` 区分查号与办理。先走确定性表达（预定、预订、订号、排门诊等），未命中的明确请求再根据语义路由。先用可见档案补资料，仍缺患者/科室则追问，办理前让用户选医院；不自动替用户选择。
- 急症规则在模型、识图和挂号前执行。单次定时提醒不进入病历计划提取。病历/药单图片和文字医嘱由 `family-aftercare` 处理，不再使用旧预后待追问状态。
- 提示词强调本次请求与历史上下文的区别、任意位置 @、口语表达、缺少信息仍是请求、查询不等于下单；提供当前上海时间ISO文本，避免相对日期猜错年份。回复应给实际结果、真实进度或必要追问，不能只有“收到”，不能在无执行结果时宣称成功。

回归样例：

| 输入 | 预期 |
| --- | --- |
| 预定明天下午的号@小艺 | 读取患者/科室档案，保留下午偏好，选择医院或追问缺项 |
| 明天下午四点的号有吗 | 触发family-appointment，精确查询次日16:00，不自动挂号；科室由当前就医上下文补全 |
| 帮我@小艺查一下号源 | 查询，不挂号 |
| 妈妈膝盖这件事，明天下午给她安排一下@小艺 | 结合语义场景与上下文，不能仅因缺“挂号”二字忽略 |
| 五分钟后提醒我吃药＠小艺 | 创建本次明确的单次提醒，不要求上传病历 |
| 妈妈说：“预定明天的号@小艺” | 不当作当前用户发起的预约 |
| 我去图书馆的安排改到后天下午 | 近况更新，不擅自建立新任务 |

聊天查号统一经过注册工具执行器：先 `skill_load(family-appointment)`，再 `hospital_simulator(action=query)`；具体时间查询、带患者的号源对比和预约前选号共用查询工具。复诊简报查号也使用该工具。查询条件及原始结果保存在工具执行记录中，加载、查询状态及结果数量关联到原始消息的执行链。医院选择卡保留原请求消息，后续查询仍归属同一条消息。查询失败与无匹配号源分开反馈，不用空结果掩盖工具错误。
