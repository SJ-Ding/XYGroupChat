# 家人帮 · 本次改进说明（2026-10-31）

> 本文记录早期 v1 实现；当前医院 v2、`family-aftercare` 和按院号源接口以 `family-care-updates.md` 为准。

目标：把原来“通用家庭群聊 + 零散的挂号/记忆能力”，打通成一条**可现场演示的家庭就医守护闭环**，并让页面更好看、更好讲。原项目已备份在 `group_work/backups/XYGroupChat-main.原始.20261031.tar.gz`。

## 一、打通的主线（以前缺失或断开的地方）

| 环节 | 以前 | 现在 |
|---|---|---|
| 主动发现 | 只有 30 秒观察后的通用跟进文本 | 长辈说“膝盖又酸了”（不用 @）→ 结合病史 + 高德天气 → 「小艺建议」卡，照护人一点就挂号 |
| 一句话挂号 | 模型自己调浏览器，随机挑第一个号 | 规则 + 档案补全四要素 → 高德驾车距离 → 多因子打分 → **号源对比卡**（推荐项、费用更低项、离家最近但约满的对比项） |
| 浏览器代办 | 随机号源、模糊选择器 | 按选定的院区/医生/时间精确代办，`data-testid` 选择器，每步**橙色高亮 + “小艺正在代为操作”横幅 + 聊天实时进度** |
| 支付 | 没有（“到院支付”） | 锁号 15 分钟 → 支付卡 → **模拟收银台**（本人点击）→ 支付回调 → 凭证卡 + 日历文件 + 就诊前 1 小时提醒 |
| 就诊后 | 没有 | 时钟拨到就诊日 → 医院生成电子病历 → **守护计划卡**（复诊/用药/康复可单独开关）→ 确认后生效 |
| 用药依从 | 没有 | 每日打卡卡（长辈大按钮）、自然语言打卡（“药吃过了”）、**7 天依从性周报**，提醒后老人打卡数字实时更新 |
| 复诊 | 只有记忆里的复诊时间提醒 | 复诊前一天自动：**查上次医生的号 + 用药/康复完成率 + 3 条建议问医生** → 一键再走锁号支付闭环 |
| 急症 | 没有 | 红旗症状规则（不调模型）→ **急诊卡**（120、原地休息、高德检索就近综合医院）+ @照护人 |
| 时间 | 只有真实时间，复诊/周报没法现场演 | **DemoClock 演示时钟**：快进 1 小时/1 天/到剧情节点，消息、提醒、号源日期全部同一时间线 |
| 演示控制 | 需要手工敲消息 | **演示导演台**：6 步剧本、以家人身份发言、快进、一键重置（3 秒回到第 0 天） |

## 三、设计取舍

1. **规则保底、大模型增强**：需求判断、槽位理解、医嘱结构化、建议问医生会调用 DeepSeek；未配置或失败时自动走规则，思考轨迹里会标明“大模型”还是“规则”。演示现场断网也能完整走完。
2. **模型负责想，代码负责做**：模型没有提交与支付能力；急症不经过模型。
3. **演示可复现**：号源按日期确定性生成，关键剧情号源固定（明早张明远 08:30 有号、东院区骨科明早约满、李建华更便宜的备选）。
4. **高德慢就预取**：公司网络下高德 MCP 单次约 7 秒，启动和重置后在后台预取距离、天气、附近急诊并缓存。

## 四、使用前需要你做的

- 在本地 `.env` 加上：`AMAP_MCP_URL=https://mcp.amap.com/mcp?key=你的高德Key`（Key 不要提交到仓库）。
- `DEEPSEEK_API_KEY` 照旧配置。本次在开发环境没有模型 Key，大模型分支用假模型做了自动化测试，**建议演示前用真实 Key 跑一遍剧本**，确认回复语气和耗时。
- Windows 上运行 `start.ps1` 会重新安装依赖并构建两个前端。
