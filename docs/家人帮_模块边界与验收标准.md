# 家人帮 · 模块功能边界与验收标准

> 对应《SR-系统需求规格说明书》SR-001～SR-010 和《架构设计方案》。
> 本文写的是**当前代码实际实现**的边界：每个模块负责什么、不负责什么、以及怎么验收。
> 自动化验收：`python -m pytest -q`（共 208 项，其中 `tests/test_care.py` 10 项覆盖本文主线）。

## 0. 总体结构（一台电脑、一个进程）

```
浏览器（家庭群聊 /?user=child · 长辈大字 /?user=mom&elder=1 · 模拟医院 /hospital/）
        │ REST + WebSocket                                   │ 页面请求号源/预约/支付
        ▼                                                    ▼
FastAPI 单进程 backend/app.py
 ├─ Agent 主循环 agent.py ──► 就医守护快速通道 care.py（规则保底 + 大模型增强）
 │        │                          ├─ 号源排序、卡片、守护计划、依从性、复诊简报、急症
 │        │                          ├─ 高德 MCP（距离/天气/附近急诊，启动预取）amap_mcp.py
 │        │                          └─ 浏览器代办 hospital_simulator.py（Playwright，data-testid）
 │        └─ 通用对话：意图分析 → Skill 目录/加载 → 工具调用 → 回复（原有能力）
 ├─ 模拟医院数据源 hospital_data.py（确定性号源、预约、支付、电子病历）
 ├─ 演示时钟 democlock.py · 演示数据 care_seed.py
 └─ SQLite（消息、记忆 FTS、卡片、任务、照护事项、打卡、轨迹）
外部：DeepSeek（可选，未配置时规则兜底）· 高德 MCP（可选，未配置时直线估算）
```

**统一原则**

| 原则 | 落地方式 |
|---|---|
| 模型负责想，代码负责做 | 锁号只能在家人点确认卡后由程序提交；支付只能本人在收银台点；急症只走规则 |
| 规则保底，模型增强 | 每个用到大模型的环节都有规则兜底，模型未配置/超时/输出不合规时演示不中断 |
| 每一步可解释 | 编排每一步写入 `care_trace`，前端「小艺在想什么」实时展示类型、细节、耗时 |
| 演示可复现 | 号源按“医生+院区+日期”确定性生成，关键剧情号源固定；一键重置回到第 0 天 |

## 1. 意图理解与主动介入（SR-001）

| 项 | 内容 |
|---|---|
| 模块 | `backend/care.py` 的 `on_message` / `handle_need_hint`；接入点 `agent.py` 的 `process` |
| 负责 | 群消息进入后先过就医快速通道：急症 → 用药打卡 → 挂号请求 → 长辈不适（未 @ 也会识别）；命中则由编排接管，不再生成通用回复 |
| 不负责 | 普通闲聊、非就医请求（交给原有的意图分析与参与策略）；不替家人做决定，只发“建议卡” |
| 大模型 | 需求判断 + 给照护人的一句话提醒（`care_hint`）；兜底为症状关键词 + 模板 |
| 验收 | ① 妈妈说“膝盖又酸又胀”（未 @）→ 数秒内出现「小艺建议」卡，含病史与天气；② 同一成员 2 小时内只提醒一次；③ “不用挂号了”“我们约了周六3号见”不触发；④ 卡上点「好的，帮挂号」直接进入挂号 |
| 自动化 | `test_elder_symptom_creates_hint_once_per_two_hours`、`test_rules_reject_negation_and_non_medical_appointments` |

## 2. 一句话挂号：号源查询与排序（SR-002）

| 项 | 内容 |
|---|---|
| 模块 | `care.handle_booking_request` / `build_options`，数据来自 `hospital_data.find_slots` |
| 负责 | 认人（“我妈”→王秀兰，或从近期聊天推断）、补科室（症状/档案）、补日期时段（偏好“上午”）、加载 Skill `family-appointment`、读医疗档案、高德驾车距离、查号、打分排序、推送号源对比卡 |
| 排序 | 距离 45% · 熟悉度 30%（去过次数）· 医生连续性 15%（上次的医生）· 职称 10%；理由由数据模板生成，不交给模型写 |
| 不负责 | 不诊断；不编造医院/医生/号源；缺就诊人时只追问一次 |
| 大模型 | 槽位理解 + 一句回复（`care_booking`），规则抽到的槽位优先，模型只补空缺 |
| 验收 | ① “@小艺 帮我妈挂明天上午的号”→ 对比卡：①总院·张明远 08:30（推荐，需授权），②总院·李建华（费用更低），东院区作为“离家最近但约满”的对比项；② 从发消息到出卡 ≤ 15 秒（规则模式毫秒级，模型模式取决于网络）；③ 思考轨迹包含 Skill 加载、medical_profile、高德、查号、打分 |
| 自动化 | `test_one_sentence_booking_ranks_options_with_rules_only`、`test_model_fills_slots_when_rules_cannot`、`test_slots_are_deterministic_and_story_slots_pinned` |

## 3. 确认卡与锁号执行（SR-003）+ 浏览器自动化（SR-009）

| 项 | 内容 |
|---|---|
| 模块 | `care.start_booking` → 工具 `hospital_simulator(action=book)` → `AppointmentManager._fill_targeted` |
| 负责 | 选号前复查号源；浏览器按 `data-testid` 逐步点击（院区→科室→日期→医生→号源→就诊人→核对→勾选须知），每步橙色高亮 + 页面顶部“小艺正在代为操作”横幅 + 聊天里实时进度；停在核对页发「门诊预约·待确认」卡；家人确认后由程序提交 |
| 不负责 | 模型没有提交与支付工具；`approve` 只能由卡片任务步骤触发；不操作真实医院 |
| 授权 | 挂号费超过 50 元必须带家人授权令牌，否则医院后端拒绝（`hospital_data.create_appointment`） |
| 验收 | ① 选号后约 4 秒出现确认卡（演示可视模式会更慢，便于观看）；② 未确认前预约记录不存在；③ 重复点确认只生效一次（卡片版本 + 幂等键）；④ 号被抢时提示并重新给选项 |
| 自动化 | `test_booking_needs_family_authorization_and_decrements_slot`、原有 `tests/test_hospital_simulator.py`；端到端用无头浏览器实测通过 |

## 4. 端到端支付闭环（SR-004）

| 项 | 内容 |
|---|---|
| 模块 | 锁号回调 `care.on_booked` → 支付卡；收银台页面 `hospital/src/pages/PayPage.tsx` → `POST /api/hospital/appointments/{id}/pay` → `care.on_paid` |
| 负责 | 支付卡（金额、锁号 15 分钟）；收银台校验支付凭证；支付成功后：支付卡变“已支付”、凭证卡（含 `.ics` 日历文件）、就诊前 1 小时提醒、写入就诊档案 |
| 不负责 | 不产生真实扣款；小艺不能代付 |
| 验收 | ① 支付卡“去收银台支付”新标签打开收银台；② 凭证无效返回 403；③ 支付后 2 秒内出现凭证卡；④ 日历文件可导入 |
| 自动化 | `test_demo_api_reset_state_and_calendar`（日历与凭证校验） |

## 5. 就诊后守护计划（SR-005）

| 项 | 内容 |
|---|---|
| 模块 | `care.complete_visit`（演示步骤 3）、`confirm_plan_items` |
| 负责 | 时钟拨到就诊当天 → 医院生成电子病历（`hospital_data.make_emr`，可在医院“我的预约”查看）→ 结构化为复诊/用药/康复三类 → 守护计划卡（每项可开关）→ 确认后写入照护事项与医疗档案 |
| 不负责 | 不新增药物、不改剂量、不推断疗程；未确认不生效 |
| 大模型 | 医嘱结构化（`care_plan`），兜底为病历结构化字段 |
| 验收 | 计划卡包含三类事项；确认后看板出现“康复中·第 N 天”和计划进度 |
| 自动化 | `test_visit_plan_adherence_and_followup_briefing` |

## 6. 用药依从性追踪（SR-006）

| 项 | 内容 |
|---|---|
| 模块 | `care.adherence_report` / `send_checkin` / `handle_checkin_text` / `simulate` |
| 负责 | 每日到点发打卡卡（长辈大按钮“已吃/稍后”）；长辈说“药吃过了”也能打卡；快进时按预设作息补齐跳过的打卡；周报卡：7 天打卡点、依从率（≥90% 绿 / 70–90% 黄 / <70% 红）、漏服日期；“提醒爸爸吃药”→ 爸爸端打卡后周报数字实时更新 |
| 不负责 | 不判断是否需要停药/加药；“未确认”不等于“没吃” |
| 验收 | 快进到第 7 天早上：爸爸漏服 2 次、今天待打卡；爸爸点“已吃”后周报从 4/6 变为 5/7 |

## 7. 复诊自动预约与就诊简报（SR-007）

| 项 | 内容 |
|---|---|
| 模块 | `care.tick` → `followup_briefing` |
| 负责 | 复诊前一天 20:00 自动：查上次医生的号、汇总两周用药/康复完成率、生成 3 条“建议问医生”；卡上“确认挂号”复用同一条“浏览器锁号→支付”闭环，“改约其他时间”给新的选项卡 |
| 大模型 | 建议问医生（`care_briefing`），兜底为模板 3 条 |
| 验收 | 卡片包含就诊人/医院/医生/时间、上次诊断、用药 13/14、康复 12/14、3 个问题 |

## 8. 家庭档案（SR-008）

| 项 | 内容 |
|---|---|
| 模块 | 原有记忆系统 `memory.py`（domain=general/medical + profile 结构化字段）+ 演示数据 `care_seed.py` |
| 负责 | 用档案代替追问：病史、过敏、常去院区、熟悉医生、用药、偏好时段；挂号成功、计划确认后自动写入新档案；看板展示“小艺记得的事” |

## 9. 演示时钟与导演台（SR-010）

| 项 | 内容 |
|---|---|
| 模块 | `democlock.py`（真实时间 + 偏移量，存于 `DATA_DIR/demo_clock.json`）、`care.run_step` / `advance_to`、前端「演示剧本」 |
| 负责 | 全系统统一的“现在”（消息时间、提醒、打卡、号源日期都随之变化）；快进 1 小时/1 天；6 个剧情步骤；一键重置回到“今天 20:10、第 0 天” |

## 10. 急症拦截（产品底线）

| 项 | 内容 |
|---|---|
| 模块 | `care.RED_FLAGS` / `handle_emergency` |
| 负责 | 胸痛伴呼吸困难、口角歪斜/单侧无力、意识不清、大出血、突发剧烈头痛 → 急诊卡（120、原地休息、高德检索的就近综合医院）+ 通知照护人；不挂门诊号 |
| 不负责 | 不做诊断；这一步**不调用大模型** |
| 验收 | 爸爸说“胸口疼得厉害，有点喘不上气”→ 急诊卡；“今天胸口有点闷”不触发 |
| 自动化 | `test_emergency_is_rule_based_and_skips_model` |

## 12. 性能指标（本机实测：规则模式、无头浏览器、高德已预取）

| 环节 | SR 目标 | 实测 |
|---|---|---|
| 长辈说不舒服 → 建议卡 | ≤ 3 s | 0.8 s（含调度器 0.5 s 轮询） |
| 点“好的” / 一句话 → 号源对比卡 | ≤ 15 s | < 0.1 s（开启大模型后增加一次模型往返） |
| 选号 → 浏览器走到核对页 → 确认卡 | — | 3.4 s（可视模式每步停顿 650 ms，约 10 s，便于观看） |
| 确认 → 锁号 → 支付卡 | ≤ 8 s | 1.6 s |
| 收银台支付 → 凭证卡 | ≤ 2 s | < 0.1 s |
| 快进 → 周报卡 / 复诊简报卡 | ≤ 2 s | < 0.1 s |
| 胸痛 → 急诊卡 | — | 0.8 s（不调用大模型） |

> 高德 MCP 在公司网络下单次调用约 7 秒（多次握手），因此服务启动和重置后会在后台预取距离、天气、附近急诊并缓存，演示时直接命中缓存。
